# Shared facility-area cache

Discovery reads saved POIs immediately. It does not wait for OSM. Visible bounding boxes are split into a shared 0.02-degree grid (about 2.2 km north/south, narrower east/west away from the equator). Existing bounding-box and rate limits still apply; very wide views ask users to zoom in.

The private PostGIS database stores tile status, completion times, leases and retry times. Every user reuses the same POIs and completion records. Successful tiles, including genuinely empty tiles, stay fresh for seven days. Reports and closures are read from POIs on every response; they are not cached in tile snapshots. UUID cursor pagination returns every saved matching facility in 500-record pages. The app publishes pages incrementally and clusters by category in dense views. A new ingestion during pagination may require the next refresh to include newly inserted IDs before the cursor.

Requests wake a continuous background queue in the existing API process. No paid worker or new hosting service is required. One process has at most one outstanding job; database claims and a shared five-second admission interval prevent duplicate work and limit all replicas to twelve tile jobs/minute. The worker drains independently of polling while recent exploration remains active, sleeps when idle, and shuts down with the API. Visible tiles take priority; a one-tile border is queued with lower priority for nearby panning. Queue admission and facility writes are batched to reduce network round trips. Each job can try two providers. Network calls hold no database connection. Failed tiles retry with exponential delay (one minute to thirty minutes). Interrupted jobs become claimable after three minutes. New requests reprioritize the viewed area; jobs not requested within ten minutes are not pursued. Render suspension can pause processing; later requests resume it.

The free-tier guardrails limit metadata to 10,000 tiles and stop new ingestion when the POI table and its indexes exceed 250 MiB. This is a conservative ingestion budget, not a guarantee that all database use fits the plan: reports, logs, indexes and other tables also consume storage. Existing data remains readable at the limit. No community records are automatically deleted.

The API exposes loading_state (ready/loading/unavailable), retry_after_seconds and tile progress. iOS displays pins as they arrive, polls loading areas at five-second intervals for twelve checks, then ten-second intervals for twelve checks, and keeps the existing foreground refresh afterward. Moving elsewhere cancels UI work; missing data is not treated as proof that facilities do not exist. Temporary unavailable areas keep saved pins and retry during later requests. ## Provider resilience

OSM requests use a 12-second server query budget, a 5-second connection timeout, and a 15-second HTTP timeout. Logs distinguish rate limits, HTTP status failures, timeouts, connection/TLS failures, invalid JSON, malformed payloads, and incomplete Overpass responses. Logs contain provider hostnames and timings, never request bounds, raw response bodies, or credentials.

Two consecutive provider failures open a process-local circuit for 60–300 seconds. HTTP 429/503 responses immediately cool down the provider; numeric Retry-After values are honored up to 900 seconds (otherwise 60 seconds). Healthy mirrors remain usable, and successful recovery clears the failure history. A custom OVERPASS_URL remains exclusive.

After a tile fails, subsequent jobs fetch one of four smaller quadrants per job. Each successful piece commits independently and immediately becomes visible. The parent tile is marked ready only after all four pieces succeed. A bounded 256-entry memory checkpoint tracks completed pieces for up to an hour between successes; restarts/eviction can repeat safe upserts, but never delete stored facilities or falsely mark a partial tile complete. No new database migration is required.

Any failed tile job pauses prefetch admission for five minutes and limits worker claims to areas requested within the last two minutes (prefetch requests are aged five minutes). Existing retry backoff and the global job budget still apply. These changes reduce wasted requests, but cannot guarantee upstream availability.
